# Правила работы в TheroDev-Corp

## Коммиты и ветки

Пишите заголовки коммитов и PR в формате `type(scope): summary`. Область `scope` необязательна. Для неё используйте строчные латинские буквы, цифры, дефисы и точки. Примеры — `fix(monitoring): retain endpoint collectors` и `chore(deps): update Teleport agents`.

| Тип | Назначение |
| --- | --- |
| `feat` | Новая возможность |
| `fix` | Исправление ошибки |
| `docs` | Документация |
| `chore` | Сопровождение, зависимости и подготовка релизов |
| `refactor` | Изменение структуры без изменения поведения |
| `ci` | Изменение CI |
| `test` | Тесты |
| `revert` | Откат изменений |

Рабочие ветки называйте `<type>/<slug>`. В `slug` используйте строчные латинские буквы, цифры и дефисы. Допустимы точки перед цифрами версии. Примеры — `fix/vmalert-remote-write` и `chore/teleport-agents-v19.0.1`.

Для существующих процессов сохраняются `renovate/*` у Renovate, `release/*` в `remnawave-node-cloud-native` и `swarm/*` в `agents-memory`. Применяйте соглашения к новым изменениям. Открытые PR и существующие ветки можно завершить с текущими именами.

## Ревью и мердж

- В описании PR укажите цель и результаты проверок. Для инфраструктурных изменений укажите затронутые кластеры и способ отката.
- Запрашивайте ревью по необходимости. Перед мерджем проверьте результаты действующих проверок и закройте обсуждения.
- Вносите изменения в `main` через PR с помощью squash merge. Используйте заголовок PR для итогового коммита. При синхронизации форка с upstream допустим merge commit, чтобы сохранить историю исходного репозитория.
- Прямой push, force push и удаление `main` запрещены правилами команды. Публичные репозитории обеспечивают это через защиту ветки. В приватных репозиториях на GitHub Free за соблюдением следят участники команды.
